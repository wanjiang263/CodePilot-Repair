# Phase28 T07 — 索引修复或旁路决策

- 日期：2026-10-30。数据来源：T03 剖析 `docs/notes/phase28-index-profile.json`
  （合成子集：450 个约 1KB 的 Python 文件，seed 20281030，**绝对耗时不可外推到
  Django 量级**）与 Phase27 冻结历史（Django 2717 文件，本轮未复跑、不混算）。
- 范围约束：零网络、零模型请求；除 Phase28 已授权的 `Indexer.__init__` 可选参数
  （`cache_max_entries` / `cache_max_bytes`）外，本轮不再改动任何生产代码。

## 结论

**走「旁路 + 文档化」（选项 4）。** `complete_closure_v2` 完整关联闭包保持为唯一
正确路径；不引入任何未经正确性证明的局部更新。`src/codepilot/repo/index.py` 模块
docstring 声明的"每次更新重建全部关联"是刻意取舍而非待修缺陷：数据库只存
files/symbols/edges，不持久化解析绑定，未解析绑定不可恢复——任何"只更新变化文件
的边"的方案，都会让未变化文件的边在跨文件改名/新增符号时悄悄失效或变陈旧。

## 机制：为什么单文件变化可能比冷索引还慢

增量一轮 ≈ 冷索引的全部阶段 − 缓存命中的解析节省 + 旧图删除/替换开销：

1. 解析侧：缓存是实例内 LRU（≤128 条且 ≤8MiB 源字节，树不持久化），增量只能
   通过 `cached_at_start` 快照复用 ≤128 棵树，其余全部重解析
   （解析数 = py 文件数 − 命中数；Django：2589 = 2717 − 128）。
2. 闭包侧：`new_symbol_ids` 覆盖全部扫描文件，`changed_source_ids` 因此是全仓库
   符号集——所有边先 DELETE 再 INSERT，TEST 边全删重插。冷索引只付 INSERT，
   增量额外多付 DELETE 与悬挂检查。
3. 当第 2 项额外开销大于第 1 项命中节省时，增量慢于冷索引。Django 大文件形态下
   两项都大（142.7 − 105.0 = 37.7s 的净差额即此差值）；子集上两项接近持平。

## 已否决的选项

- **选项 1：TEST 边按文件局部重建。** 收益上限 ~3.3%（提取 1.75% + 写回 1.6%）；
  且未变化测试对改名/新增符号的 TEST 目标重绑定正是完整闭包保证的语义（
  test_index.py 的 medium 自愈用例钉住它），局部化会破坏 → 不做。
- **选项 2：按文件增量更新边。** 未变化源文件的出边依赖变化文件的符号集合
  （改名/新增/删除都会让旧边失效或错过重绑定），未解析绑定不可恢复 →
  正确性不允许，不做。
- **选项 3：抬高缓存默认值。** 保持 128 条 / 8MiB（S4 裁决一致）。Django 大文件
  形态下 8MiB 源字节上限先于条数上限绑定，只抬条数无效；抬字节上限等于把全部
  解析树常驻内存（2717 棵），是无界内存风险；子集数据显示收益上限 ~11% → 不做。

## 采纳：选项 4（旁路 + 文档化）的用户可见路径

- 无变化：`verified_snapshot_v2` 指纹 + sha 校验通过即返回，不解析、不写图。
- 有变化 / 指纹变化：`complete_closure_v2` 完整闭包——与"同一仓库状态下的全新
  全量索引"逐字段等价（等价性断言在 tests/unit/repo/test_index.py），是有正确性
  保证的回退，不是退化。
- 本决策不承诺任何提速百分比；性能改进留给满足下述先决条件的后续阶段。

## cache_max_entries / cache_max_bytes 参数定位

Phase28 授权加入的 **opt-in 实验通道**（剖析脚本使用），默认 128 / 8MiB 与历史
行为完全一致；4 个生产调用点均用默认值。回归测试
`test_cache_capacity_parameters_take_effect` 与
`test_default_cache_bounds_match_explicit_128`（tests/unit/repo/test_index.py）
分别钉住"两个上界真实生效（含复用语义不变）"与"默认构造 = 显式 (128, 8MiB)"。

## 限制与下一阶段条件

- 剖析子集只有 450 个小文件：占比结构（闭包 ≫ 解析）与 Django 侧一致，但比例
  数值不可直接搬用；Django 结论以 Phase27 冻结数据为准。
- 安全的局部闭包需要先满足其一（列为未来条件，不做无据承诺）：
  1. 数据库持久化解析绑定（模块/名字 → 符号 id 的绑定表），增量时未变化文件
     依靠持久化绑定重绑定出边；
  2. 可复算的绑定指纹（绑定结果可由内容 + 符号集推导，无需解析树）。
  在此之前，完整闭包是唯一被证明正确的路径；本决策即"旁路"的含义。
